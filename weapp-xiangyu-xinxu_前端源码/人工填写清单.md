## 1. 逐项详解

### A1. 小程序 AppID

**位置**：`project.config.json` 第 4 行

```json
"appid": "touristappid",
```

**现在**：`touristappid` 是微信的「游客/测试号」，**只能在模拟器里看，不能真机预览、不能上传**。

**改成**：你自己的 AppID（形如 `wx1234567890abcdef`）。
AppID 在哪拿：微信公众平台 <https://mp.weixin.qq.com> → 注册小程序 → 开发管理 → 开发设置 → AppID。

> 只是答辩用模拟器演示的话，**这项可以不填**。

### A2. 图片素材（最影响观感的一项）

**现状**：`mock/` 里所有图片地址都是占位域名 `https://cdn.example.com/...`，**永远加载不出来**。
代码已经做了兜底（显示成带名字的色块），所以不会报错、不会白屏，但看着不精致。

**共 37 张，分布如下**：

| 文件 | 张数 | 字段 | 用在哪 |
| --- | --- | --- | --- |
| `mock/mock-material.js` | 2 | `coverUrl` | 拼贴模板封面 |
| `mock/mock-material.js` | 8 | `imageUrl` | 拼贴素材图（童趣 4 + 复古 4） |
| `mock/mock-material.js` | 1 | `composeResult.imageUrl` | 合成结果图 |
| `mock/mock-nfc.js` | 6 | `historyImageUrls` | 4 个标签的史料图（2/1/2/1 张） |
| `mock/mock-map-spots.js` | 5 | `imageUrl` | 地图点位配图 |
| `mock/mock-goods.js` | 5 | `coverUrl` | 商品封面 |
| `mock/mock-goods.js` | 7 | `detailImageUrls` | 商品详情长图 |
| `mock/mock-goods.js` | 3 | `orders[].coverUrl` | 订单里的封面快照 |

**怎么改（两种办法，选一种）**：

**办法 1：用本地图片（最简单，不用域名，推荐新手）**

1. 在项目根目录建 `assets/images/` 文件夹
2. 把图片拷进去，命名用英文/数字，例如 `mat-childlike-01.png`
3. 把 mock 里的地址改成 `/assets/images/xxx.png`

改前：
```js
imageUrl: 'https://cdn.example.com/xiangyu-xinxu/material/mat-childlike-01.png',
```
改后：
```js
imageUrl: '/assets/images/mat-childlike-01.png',
```

> ⚠️ 注意：小程序整包有 **2MB** 限制。图片多的话先压一下（推荐 webp 或压缩后的 png/jpg），或者用办法 2。

**办法 2：用图床 / 自己的服务器**

把 `https://cdn.example.com/...` 全部换成你真实的图片地址（必须 `https`）。好处是不占包体积，坏处是要在后台配 `downloadFile` 域名。

**怎么快速找到全部要改的地方**：
在开发者工具里按 `Ctrl+Shift+F` 全局搜索 `cdn.example.com`，一共 **61 处**（37 张图 + 24 段音频），逐个替换。

### B3. 地图点位（`mock/mock-map-spots.js`）

现在是我编的 5 个点位（客家围屋 / 圆形土楼 / 擂茶老铺 / 花灯工坊 / 古渡口）。

**要改的字段**：

```js
{
  spotId: 'spot-01',        // 点位 ID，被商品和 NFC 标签引用，改了要一起改
  name: '客家围屋',          // 地点名称
  mapX: 168,                // 在手绘底图上的 X 坐标（设计稿 750 宽下的像素）
  mapY: 420,                // Y 坐标（设计稿 1334 高下的像素）

  imageUrl: '...',          // 点位配图（见 A2）
  latitude: 24.2886,        // 真实纬度，导航用
  longitude: 116.1225       // 真实经度
}
```

> **两处最容易搞错的地方**：
> 1. `mapX` / `mapY` 是**设计稿 750×1334 上的像素**，不是百分比。如果你换了底图，底图必须也是 750×1334，否则要改 `pages/local-map/local-map.js` **第 23 行** 的 `MAP_DESIGN = { width: 750, height: 1334 }`。
> 2. `latitude` / `longitude` 是**真实经纬度**，点「导航到这里」会打开微信地图。现在这 5 组是梅州一带的近似值，**不是真实地点**，答辩想演示导航就换成真实坐标（用高德/腾讯地图拾取坐标工具查）。

### C5. 微信支付与手机号登录（要接才看）

这两个能力**前端已经写完**，但要真正跑起来，缺的是「资质 + 后端」，不是代码。

**① 微信支付**

| 要做的事 | 在哪做 |
| --- | --- |
| 申请**微信支付商户号**（`mchid`） | 微信支付商户平台 <https://pay.weixin.qq.com>，需**企业主体** |
| 后端实现**统一下单 + 签名**（v3 规范） | `POST /goods/orders`、`POST /goods/orders/{orderId}/pay`，见 `API_DOC.md` 3.12 / 3.13 |
| 打开前端支付开关 | `utils/api.js` 里把 `const PAY_ENABLE = false;` 改成 `true` |
| 关掉 mock | `utils/api.js` 里 `USE_MOCK` 改成 `false` |
| 配支付相关域名 | 小程序后台 → 开发设置 → 服务器域名 |

> ⚠️ **个人主体小程序根本不能用微信支付**，会直接报错。
> 演示/答辩请保持 `PAY_ENABLE = false`（模拟支付），页面照样能走完整个下单流程。
> 两个开关是「与」关系：只要 `USE_MOCK` 还是 `true`，就算 `PAY_ENABLE = true` 也不会真扣款。

**② 微信手机号一键登录**

| 要做的事 | 在哪做 |
| --- | --- |
| 小程序主体**已认证** | 公众平台 → 设置 → 基本设置（个人主体拿不到手机号） |
| 隐私指引里**声明手机号**用途 | 公众平台 → 设置 → 服务内容声明 → 用户隐私保护指引 |
| 后端用 `phoneCode` 换手机号 | 调微信 `phonenumber.getPhoneNumber`，见 `API_DOC.md` 3.14 |

> mock 阶段点登录拿到的是假号 `13800138000`，用于演示界面；真实手机号前端**永远拿不到明文**。

**③ 收货地址**：纯本地功能，存 storage（键 `MY_ADDRESSES`），**不需要任何配置**，开箱即用。

### D1. 后台「用户隐私保护指引」（真机保存海报必须）

微信从 2023 年起要求：调用相册写入等接口前，必须在小程序后台声明用途，否则**真机上会直接失败**（模拟器不受影响）。

**操作**：微信公众平台 → 设置 → 服务内容声明 → 用户隐私保护指引 → 勾选并填写：
- **相册（仅写入）** —— 用于「保存拼贴海报到相册」
- 如果要用扫码演示，可能还需要 **摄像头** —— 用于「扫描标签二维码」

不配的后果：真机点「生成海报并保存」会提示权限失败（代码里已经做了兜底提示，但确实存不进相册）。

## 附录 G：地图定位的标定（新增功能，必读）

定位功能已经写好了，但要「在手绘图上准确地画出你的位置」，需要你亲手填 **2 组锚点**。

### G1 先理解现状（不用改代码就能跑）

| 状态 | 现在是什么样 | 你要做什么 |
| --- | --- | --- |
| 演示模式（默认） | `utils/geo.js` 里 `LOCATION_ENABLE = false`，用模拟位置（擂茶老铺南边约 180 米），界面标「模拟」 | 什么都不用做，答辩能直接演示 |
| 真实定位 | 改成 `true` 才会调 `wx.getLocation` | 先在后台申请「地理位置接口」，见 G4 |

**为什么现在不画那个朱红圆点？** 因为 `mock/mock-map-spots.js` 里 5 个点位的经纬度是占位数据，彼此尺度不一致（拟合残差 256 px，远超 60 px 阈值）。这时画"精确落点"就是在骗人，所以页面自动退化成「用虚线圈住离你最近的点位 + 告诉你距离和方向」。

### G2 想看到精确圆点，填这两组锚点

打开 `utils/geo.js`，找到：

```js
const CALIBRATION = [];
```

用手机在两处**你确切知道经纬度**的地方各取一次坐标（手机指南针 App / 高德地图长按看坐标都行，坐标要 GCJ-02），再在手绘图上量出这两个点对应的像素位置（750×1334 设计稿），填成这样：

```js
const CALIBRATION = [
  { latitude: 24.2886, longitude: 116.1225, mapX: 168, mapY: 420 },
  { latitude: 24.3014, longitude: 116.1308, mapX: 302, mapY: 742 }
];
```

- 两组点**离得越远越好**（别在同一个院子里取）
- 填完重新编译，页面上会出现朱红圆点 + 呼吸环，说明标定通过了
- 控制台如果还打印「标定残差过大」，说明这两组坐标或像素位置有一个填错了

### G3 三个阈值在哪调

| 常量 | 默认 | 含义 |
| --- | --- | --- |
| `RMS_TOLERANCE_PX` | 60 | 残差小于它才画精确圆点 |
| `HERE_METERS` | 60 | 小于它文案说「你就在 XX」 |
| `NEAR_METERS` | 2000 | 小于它文案说「你在这附近」 |
| `LOCATION_TTL_MS` | 60000 | 定位缓存，避免切 tab 反复弹权限 |

### G4 要开真实定位，后台三件事

1. mp 后台 → 开发管理 → 接口设置 → **地理位置**，申请开通 `wx.getLocation`（个人主体通过率低，类目要匹配）
2. mp 后台 → 设置 → 服务内容声明 → **用户隐私保护指引**，勾选「位置信息」
3. 代码里 `utils/geo.js` 的 `LOCATION_ENABLE` 改成 `true`

`app.json` 里的 `requiredPrivateInfos` 和 `permission.scope.userLocation` 已经替你写好了，不用动。

**没批下来也能演示**：权限被拒时页面会显示「没开定位权限 · 点小狗一样能导航」+「去设置」，不会白屏。

### G5 精确定位的现实路径（2026-11 补充，实测）

**微信的硬规则**：`app.json` 的 `requiredPrivateInfos` 里，`getLocation`（精确）与 `getFuzzyLocation`（模糊）**互斥**，同时声明会直接报配置错误、整包起不来。所以只能二选一，没有"精确失败降级模糊"这种好事。

| 你想要的 | 声明什么 | 代码里改什么 | 审核难度 |
| --- | --- | --- | --- |
| 精确（米级） | `["getLocation"]` ← 已配好 | `LOCATION_MODE = 'exact'` ← 已配好 | 难：类目必须是旅游/生活服务等，且与"精确位置"强相关 |
| 模糊（约 1 公里） | `["getFuzzyLocation"]` | `LOCATION_MODE = 'fuzzy'` | 相对容易 |
| 演示 | 保持 `["getLocation"]` 也行 | `LOCATION_MODE = 'off'` | 不需要审核 |

**申请精确位置时的写作要点**（在"场景说明"里）：

> 用户到达线下点位后，需要判断是否已抵达该点位（50 米以内）以触发讲解与打卡，因此需要精确位置；不采集轨迹、不上传服务器、不用于广告推荐。

写"推荐附近"会被认为用模糊定位足够；写"到达判定"才名正言顺要精确。

**⚠️ 接口批下来了还有一步**：必须在 `utils/geo.js` 的 `CALIBRATION` 里填 2 组真实坐标 + 图上像素（见 G2），否则标定残差过大，页面仍只会圈最近点位、不画精确圆点。

**没有位置接口也能做到"精确"的两条土办法**（都不需要任何审核）：

1. **NFC 碰一碰**：贴纸在哪，用户就在哪。项目里已有 `mock/mock-nfc.js`。
2. **扫码到位**：每个点位贴一张二维码，用户扫码即"到达"，精度 = 点位精度。`wx.scanCode` 不需要位置权限。答辩时评委扫桌上的码就能演示"到达"。
