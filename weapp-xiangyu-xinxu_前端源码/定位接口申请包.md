## 一、先确认你要申请的是"精确"，不是"模糊"

| | `getLocation`（你要的） | `getFuzzyLocation` |
| --- | --- | --- |
| 精度 | 米级 | 约 1 公里 |
| 审核 | 严，看类目 + 场景 | 松一些 |
| 两者关系 | **互斥**：`app.json` 里同时声明会直接报错、整包起不来 | |

> 实测报错原文：`app.json: requiredPrivateInfos 'getFuzzyLocation' 与 'getLocation' 互斥`
> 所以只能选一个。本项目的 `app.json` 现在声明的是 `getLocation`。

## 四、场景说明（直接复制，二选一）

**A. 短版（字数有限制时用）**

> 本小程序为客家围屋文化导览工具。用户到达围屋、土楼、擂茶铺等线下点位后，需要判断自己是否已抵达该点位（50 米以内）以触发讲解与打卡记录，因此在用户主动进入地图页时获取一次精确位置。位置仅在小程序内用于计算用户与点位的距离和方位，不采集轨迹、不上传服务器、不用于广告推荐。

**B. 详版（能写长就用这个）**

> **功能说明**：本小程序提供五处线下点位（客家围屋、圆形土楼、擂茶老铺、花灯工坊、古渡口）的文化导览服务。用户到达现场后，进入"手绘地图"页面，小程序获取一次用户当前位置，计算其与五处点位的距离和方位，并在手绘地图上标出用户所处区域，引导用户前往最近的点位。
>
> **为什么需要精确位置**：本功能的核心是"到达判定"——当用户与某点位的距离在 50 米以内时，才判定为已抵达并触发该点位的讲解与打卡。1 公里精度的模糊位置无法区分用户已到达哪个点位，也无法完成到达判定，因此必须使用精确位置。
>
> **触发时机**：仅在用户主动切换到"手绘地图"页面时获取，60 秒内不重复获取；用户拒绝授权后不再询问，改为展示点位列表。
>
> **数据用途**：位置数据仅在小程序本地用于距离与方位计算，不写入本地存储、不上传服务器、不用于用户画像或广告推荐。

**截图时把下面这句也写进说明**（重要）：

> 本项目当前未对位置做任何持久化存储与服务端上传，可在代码中核对 `utils/geo.js`（纯本地计算）。

## 六、审核通过后要做三件事

1. 确认 `app.json` 仍为 `"requiredPrivateInfos": ["getLocation"]`（已是）
2. 确认 [utils/geo.js](utils/geo.js) 里 `LOCATION_MODE = 'exact'`（已是），`LOCATION_FALLBACK = false`（已是，因为互斥）
3. **填标定**：`utils/geo.js` 的 `CALIBRATION` 填 2 组「真实经纬度 + 图上像素」
   - 不填也能用，但只能显示"离你最近的点位"，画不出精确红点
   - 现场取点：手机指南针 App 或高德地图长按取坐标（GCJ-02），图上像素在两处点位旁读取

## 七、被拒了怎么办

| 拒绝理由 | 对策 |
| --- | --- |
| 类目与位置能力不匹配 | 换类目；个人主体通常只能选到少数类目，这是最常见的死因 |
| 场景说明太笼统（"提升用户体验"） | 换成第四节文案，必须出现"到达判定 / 50 米"这种**只有精确位置才能做**的描述 |
| 无截图或截图看不出定位 | 按第五节 4 张补齐 |
| 个人主体无法申请该能力 | 换主体：个体工商户营业执照注册企业主体小程序，类目对齐后再申请 |
| 说明里写了"推荐附近商家 / 广告" | 删掉这类描述，会直接被认定模糊定位足够 |

**补正建议**：被拒后可以改材料重申，不是一次定生死；但类目不匹配这种硬伤，重提也没用。

## 八、兜底：没有权限时，答辩怎么答（诚实且不丢分）

如果评委问"这个定位是真的吗"，标准答法：

> 定位功能已经完整实现，包括精确位置、失败降级、权限引导三条链路。当前演示环境使用的是模拟位置（界面左下角有"模拟"标记），因为「精确地理位置」接口需要小程序主体与类目审核，还在审批中。接口通过后只需改一个常量，无需改动任何业务代码。

同时演示这三件事，证明不是空壳：

1. 点「重新定位」，状态从"模拟"变成"接口未开通 · 示意位置"——证明它真的在调接口、真的在做错误分类
2. 点任意小狗 →「导航到这里」→ 真机拉起微信地图，**这一步是真的，不依赖任何审批**
3. 地图上虚线圈住离你最近的点位，下方显示距离与方位——这条计算逻辑是真实的，只差真实坐标输入
