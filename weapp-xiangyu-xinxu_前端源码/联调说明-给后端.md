# 联调说明（给后端同学）

> 这份是微信原生小程序前端，**零依赖**：没有 npm、没有 node_modules、没有构建步骤，导入开发者工具就能跑。
> 接口清单见同目录的 `API_DOC.md`（15 个接口，含请求参数与响应字段）。

---

## 一、怎么打开

1. 微信开发者工具 → 导入项目 → 目录选这个文件夹
2. AppID 填 `wx1adfdc8203c1e9ad`（**需要被加为项目成员**；没权限就先用自己的测试号，本地预览不受影响）
3. 打开后应该直接进首页，不需要登录、不需要后端

---

## 二、怎么指向你的服务（两步）

打开 `utils/api.js`，改这两个常量：

```js
const USE_MOCK = false;                      // 关掉假数据，走真接口
const BASE_URL = 'https://你的域名/api';      // 结尾不要带 /
```

`BASE_URL` 会跟接口路径直接拼：`BASE_URL + '/goods/list'`。

**域名要求**：mp 后台 → 开发管理 → 开发设置 → 服务器域名 → request 合法域名，必须 https 且已备案。
本地调试可以先绕过：开发者工具右上角「详情 → 本地设置 → 不校验合法域名、web-view 域名、TLS 版本以及 HTTPS 证书」。

## 三、返回格式约定（已经内置解包，不用前端改）

```json
{ "code": 0, "msg": "ok", "data": { } }
```

| 情况 | 前端行为 |
| --- | --- |
| `code` 为 `0` 或 `200` | 把 `data` 交给业务层 |
| 其他 `code` | 抛错，`err.message = msg`，`err.code = code`，页面上会看到你写的 msg |
| 直接返回数组 / 没有 `code` 字段 | 原样透传（不套信封也行） |
| HTTP 非 2xx | 抛错「请求失败，HTTP 状态码 xxx」 |

如果你的格式不一样，改 `utils/api.js` 里 `UNWRAP_ENVELOPE = false` 即可透传原始响应。

## 五、四件需要你注意的事（不是 bug）

**1. 目前请求不带 token**
`login` 拿到的 token 只存在本地（`USER_KEY`），请求头里**还没带 Authorization**。
需要的话告诉我，我在 `utils/api.js` 里加 3 行拦截器。

**2. 支付是模拟的**
`utils/api.js` 里 `PAY_ENABLE = false`，前端不会调 `wx.requestPayment`，也不会真的走统一下单。
要做真支付，需要：企业主体小程序 + 微信支付商户号 + 后端统一下单签名，再把 `PAY_ENABLE` 改成 `true`。

**3. 图片/音频是占位地址**
37 张图片、24 段音频都指向 `cdn.example.com`，会显示成色块或播放失败，这是**预期行为**，等美术资源到位再换。判断"前端是否正常"时请忽略这些。

**4. 地图点位的经纬度必须是真实的**
`GET /api/map/spots` 返回的每个点位，`latitude` / `longitude` 要是真实 GCJ-02 坐标（不是 BD-09），并且要和手绘底图上的 `mapX` / `mapY` 对得上。
否则前端没法把"你的位置"投到图上，只能显示"离你最近的点位"。

## 六、怎么快速验证通了

1. `USE_MOCK = false` + 填好 `BASE_URL`
2. 开发者工具 → 调试器 → Network 面板，看请求是否发出、返回是否 200
3. 点进「商城」tab，如果商品列表来自你的接口，说明链路通了
4. 页面上有 loading / 空态 / 错误文案三种状态，接口报错时会在页面上显示你返回的 `msg`

## 七、代码结构（方便你定位）

```

mock/         假数据（USE_MOCK = false 后不再使用）

utils/geo.js  定位换算（纯前端计算，不需要后端参与）
pages/        11 个页面
assets/       本地图片（地图、tabBar 图标）
```
